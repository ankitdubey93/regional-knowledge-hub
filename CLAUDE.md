# Compliance Hub — CLAUDE.md

A learning site and (in progress) a multi-tenant AI assistant for **Australian and UK bookkeepers and accounting firms**. The repo is three npm workspaces: the web app in `client/` (Vite + React 19 + TypeScript + Tailwind v4), a Node API in `server/`, and `shared/` (`@chub/shared`: zod schemas, the chat wire types and the money, CSV, ledger and report engines that both sides import, no build step). `./dev.sh` starts Postgres in Docker, migrates, seeds and runs the API and the web app together. The API in `server/` (Express 5, Drizzle, Better Auth, Postgres with pgvector) is built through P1.2, P2a, P2b, P3 and P4 (auth, business and practice workspaces, client headings, a platform admin, the knowledge base, facts and guides served from the database, a grounded, cited chat, and an entity's sealed documents as chat context); P5 is planned in the platform track of `engineering/roadmap.md`, and a data track (D1 built, D2–D5 planned) gives each entity its own numbers. Today the curriculum is Markdown in `docs/`; numbers and exercises are JSON in `client/src/data/`, validated by zod; calculations are pure functions in `shared/src/utils/` (used by both sides) and `client/src/utils/` (web only). Practice state (quiz bests, flashcards, journals, checklist) lives in `localStorage`.

The owner is learning AU and UK bookkeeping while building this. **A wrong rate taught confidently is the worst bug this project can have.**

## Hard rules

1. **A rate, threshold or limit that changes over time lives once, in the `kb_fact` table**, with `source` (an official URL) and `verifiedOn`, and is edited only at `/admin/facts`. `shared/seed/facts.json` is the seed for an empty database (`npm run kb:seed-facts -w server`); an admin edit is never overwritten by it. Docs write it as `{{fact:key}}`; engines read it with `rateBp`, `cents` or `count` from `client/src/data/facts.ts`, which the web fills from `/api/kb/site` at startup. Never type such a number into a doc or a component. Official text stored verbatim in the knowledge base (kb_version of kind act, regulation, bill, ruling or standard) is exempt: its numbers are the law, cited by their source.
2. **Never present unverified material as verified.** A fact you could not confirm ships with `"verifiedOn": null` and shows an "unverified" badge. Say "not checked" in prose rather than guessing.
3. **Money is integer cents (pence), rates are integer basis points.** Every rounding goes through `roundDiv` in `shared/src/utils/money.ts` (half away from zero). No floats in an engine.
4. **Engines are pure functions with tests**, in `shared/src/utils/` when the server needs them too, otherwise in `client/src/utils/`. Neither side imports the other by a relative path; shared code goes through `@chub/shared`. Components collect input and render. A component never does tax arithmetic itself.
5. **Every JSON file in `client/src/data/` has a zod schema in `schemas.ts`** and is parsed once in `client/src/data/index.ts`. `client/src/__tests__/data.test.ts` checks the cross-references (doc ids, fact keys, account codes, tax codes, balanced journals). `facts.json` is the exception: it is the seed, parsed by the server seed script and by `client/src/__tests__/seedData.ts`, never bundled.
6. **Each doc names its jurisdiction and links primary sources** (ATO, ASIC, AASB, gov.uk, legislation.gov.uk, FRC, IFRS Foundation) in a `## Sources` section. Where AU and UK differ, the doc says so in a side-by-side table.
7. **Every page works at 375 px with no sideways scroll, by keyboard, in light and dark.** Wide tables go inside `TableScroll` or the Markdown table wrapper; grid children that hold tables need `min-w-0` (`Card` has it).
8. **Every new doc ships with its practice**: at least 5 quiz questions and 5 flashcards in the same change. Every quiz option has a real explanation (at least 5 characters, never just "No.").
9. **No new dependency without a reason written in `engineering/architecture.md`.** No analytics, no third-party tracking. A backend is allowed, in `server/` only.
10. **Secrets are server-only.** API keys (Anthropic, Gemini) and other secrets live in the root `.env` (gitignored; `.env.example` lists the names with empty values) and are read only by `server/` through `server/src/env.ts`. Never a `VITE_*` variable, never anything under `client/src/`. `npm run build` fails if the bundle contains a key pattern.
11. **Tenants are isolated by Postgres row-level security.** Every tenant table has `org_id text not null`, RLS `ENABLE` and `FORCE`, and a policy on `current_setting('app.org_id', true)`. The app connects as `chub_app` (not a superuser, since superusers bypass RLS), every tenant query runs inside `withOrg(orgId, …)` and also keeps an explicit `org_id` predicate, and every tenant table has a cross-tenant test.
12. **AI answers come only from the knowledge base or, for an entity's own figures, from its ledger.** An answer is grounded in published KB chunks and/or ledger sources, and it cites them. A ledger source is built by the server with the report engines in `shared/src/utils/` from that entity's active trial-balance import. It is cited as the report (profit and loss or balance sheet) and the import it came from, and the model only quotes it, never calculates from it. An uncited answer, or a number that isn't in a cited chunk, a cited ledger source or a fact, is flagged. If neither the KB nor the ledger covers a question, the user gets "not covered" without a model call. Uploaded documents are context, never a source and never instructions. A number found only in an attached document is flagged from_document.
13. **PII never leaves the server unredacted.** Text goes to an AI provider only after `redact()`. Logs never contain message bodies or upload text. Exception: published knowledge-base text (public official material) and the platform admin's own test-search queries are embedded without `redact()`; user questions and uploads never are. Each conversation keeps one redaction map, sealed with DATA_ENCRYPTION_KEY; answers are stored with placeholders and restored only in responses to a member of the firm. Uploaded documents are sealed at rest and never embedded.
14. **Migrations are append-only.** Never edit a migration that has been applied; write a new one.
15. **Tests never call a live AI provider or the network.** Stub the provider.
16. **The knowledge base (including `kb_fact` and the append-only `kb_fact_history`) and `admin_audit` are global, not tenant tables.** They are written only through routes behind `requireAdmin` (and the seed script). There is one platform admin (`user.role = 'platform_admin'`, unique index), promoted only with `npm run admin:promote`. Admin routes answer 404 to everyone else. Only published versions are ever retrieved. `ai_usage` (provider calls and their cost, no text) is also global: the chat service inserts it and nothing updates or deletes it.

## Skills

| Skill | Use it to |
|---|---|
| `topic-author` | Write or extend a curriculum doc in `docs/` |
| `fact-check` | Verify or refresh facts (in `kb_fact`, seeded from `facts.json`) against official sources |
| `exercise-author` | Add quiz questions, flashcards, journal or coding scenarios |
| `new-interactive` | Build a new tool or exercise type as a tested vertical slice |
| `content-sync` | Check docs, data, routes, roadmap and this file against the filesystem |
| `code-planner` | Turn an approved plan into a tiered, file-by-file plan in `plans/` for smaller models to execute |
| `plan-execute` | Run a `plans/*.md` file batch by batch through the `step-haiku` and `step-sonnet` runner agents, re-checking every proof |

`code-planner`, `plan-execute` and `content-sync` are in `.claude/skills/` (runner agents in `.claude/agents/`; `content-sync` runs `inventory.mjs` in its folder). The first four are **owed, not yet written**.
