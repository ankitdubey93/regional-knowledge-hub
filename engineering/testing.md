# Testing

```bash
npm run test:web    # all web Vitest files (243 tests, 20 files); `npm test` runs web then server
npm test -w server  # server tests (341 tests, 25 files); needs the database
npm test -w client -- src/__tests__/tax.test.ts   # one web file
npm run typecheck  # three workspaces, then the e2e folder
npm run test:e2e    # Playwright: 161 tests, about 5 minutes; needs Docker Postgres up and system Chrome
npm run lint        # inside a git repository (oxlint follows .gitignore)
```

## Conventions

- `setup.ts` fills the facts and docs registries (`setFacts`, `setDocs`) before every test from `client/src/__tests__/seedData.ts`, which parses `facts.json` and the `docs/` files itself. No test renders the app through `KbGate` except `kb-store.test.tsx`.
- Engine tests use hand-worked numbers, written as integer cents, with the working in a comment when it is not obvious.
- Component tests render through `renderAt` in `client/src/__tests__/render.tsx` (router + progress provider) and query by role and accessible name.
- `setup.ts` runs RTL `cleanup()` and clears `localStorage` and `sessionStorage` after every test.

## Server tests

```bash
docker compose up -d db
npm test -w server
```

- `client/src/__tests__/globalSetup.ts` drops and recreates the `public` schema and the `drizzle` schema of `chub_test`, then runs every migration as the owner, so each run starts from an empty, migrated database.
- `testEnv.ts` holds the test settings (local Docker credentials, a throwaway auth secret, loopback URLs); `vitest.config.ts` passes them as `env`, so no `.env` is needed.
- Tests reach the app through `startApp()` in `server.ts` on `127.0.0.1` and an ephemeral port. The suite is 1 health test, 3 auth tests (`auth.test.ts`), 23 client cases (`clients.test.ts`), 11 workspace cases (`workspaces.test.ts`) and the P2a files below. The isolation ones are 6 to 8 (firm B cannot read, update, delete or list firm A's clients) and 13 to 15 (the app role sees no rows without `app.org_id`, `withOrg` cannot insert a row for another firm, and `chub_app` is not a superuser and cannot bypass RLS). Case 14 reads the RLS error from `.cause`, because Drizzle wraps Postgres errors. P7 (the database rejects a UK trust without the API), P8 (one self row per workspace, unique violation `23505`) and W11 (switching workspace switches the client list, still scoped by RLS) are the isolation and invariant cases for the workspace work.
- `ledger.test.ts` (21 cases, including LG-R1 deleting the active import reactivates the one it superseded and LG-R2 deleting a superseded import leaves the active one alone): import, reports, superseding, a user's class surviving a re-import, currency checks, and the cross-tenant cases for `ledger_import`, `ledger_account` and `ledger_balance` (404 for firm B, RLS with no `app.org_id`, `withOrg` cannot insert for another firm, composite foreign keys refuse another firm's client).
- P2a files (79 cases): `admin.test.ts` (A1 to A11: 404 for signed-out and ordinary users, listing and filtering, sign-up cannot set a role, one platform admin in the database, ban ends the session and is audited without the reason, unban, no self-ban, `chub_app` cannot delete from `admin_audit`); `kb-text.test.ts` (T1 to T9: normalising and chunking, no database); `kb-rules.test.ts` (R1 to R10: official URLs, validation, diff, rank fusion); `kb.test.ts` (K1 to K25: the admin KB routes against Postgres, including search, one published version per source, bills, withdraw, audit, embedding with a fake embedder, upload and fetch; K25 uploads a real PDF, which arrives as a Node `Buffer`); `embed.test.ts` (E1 to E6: the Gemini client against a stubbed `fetch`); `kb-extract.test.ts` (X1 to X5: HTML, PDF and DOCX); `kb-fetch.test.ts` (F1 to F8: the allowlist, redirects, size and type limits); `kb-seed.test.ts` (S1 to S5: seeding the curriculum is idempotent and publishes a new version when a doc changes). `makePlatformAdmin` in `helpers.ts` demotes the earlier test admin, because the database allows one. The global KB and audit tables are not tenant tables, so they need no cross-tenant test.
- P2b files: `fact-rules.test.ts` (8: `resolveVerifiedOn`, `checkFactSave`), `admin-facts.test.ts` (AF1 to AF10: 404 for non-admins, create, duplicate, non-official source, unit change, confirm, re-chunk of a published guide and not of a superseded one, history append-only for `chub_app`, nothing changed), `kb-public.test.ts` (the public routes: published only, no session; it deletes the rows it created in `afterAll` through the owner role so test order does not matter), and the rewritten `kb-seed.test.ts` (S1 to S8, F-S1, F-S2, plus the `unknown_fact` cases in `kb-rules.test.ts`).
- P3 and P3b files (102 cases): `chat-text.test.ts` (36, no database: RD1 to RD12 `redact`, PR1 to PR6 the prompt, GR1 to GR9 grounding, CV1 and CV2 coverage, PC1 to PC7 pricing (PC6 Sonnet 5.5 cache reads at 0.05x, PC7 `gemini-2.5-flash` is priced), SS1 and SS2 SSE); `chat-ledger.test.ts` (L1 to L12, no database: `isLedgerQuestion`, `pickComparison`, the exact ledger source text with and without a comparison, display names, redaction of account names, the 400-line cap); `chat-tables.test.ts` (T1 to T12: the three chat tables are invisible without `app.org_id` and to another firm, `withOrg` cannot insert for another firm, composite foreign keys, the scope and status checks, `chub_app` can insert but not update or delete `ai_usage`, deleting a client deletes its chats); `chat-providers.test.ts` (AN1 to AN6 the Anthropic client and GM1 to GM4 the Gemini client, both against a stubbed `fetch`); `chat.test.ts` (C1 to C32: the conversation and message routes over SSE with a stub provider and a fake embedder: grounded answers, flagged answers, not-covered answers that never reach the provider, redaction before the provider, the spend guard and per-user limit, a stopped stream, cross-firm 404s; C28 to C32 answer from an entity's imported books and cite the report, flag a figure the model calculated, are not covered without a provider call for an entity with no import or a hub chat, and keep firm B out of firm A's books). `stubProvider.ts` and `kbFixtures.ts` are the helpers; `testEnv.ts` sets no AI keys.

- No test calls an AI provider or any host other than loopback and the local database (Hard rule 15).
- Not tested: a live Anthropic call, the Gemini request shape against a real endpoint, and the coverage thresholds against real questions.

## Browser check (`npm run test:e2e`)

`npm run test:e2e` runs Playwright (`playwright.config.ts`, specs in `e2e/`). It starts its own stack: the database `chub_e2e` on the Docker Postgres at 5437 (dropped, migrated and seeded each run by `server/scripts/e2e-db.ts`), the API on 5193 and the web app on 5192 (the Vite proxy follows `CHUB_API_ORIGIN`). The dev servers on 5190 and 5191 are not touched. It uses the system Chrome (`channel: 'chrome'`, nothing downloaded) and both AI keys are empty, so no provider is called. A `setup` project creates three users through the API (`e2e-user`, with a practice, the AU client "Browser Books Pty Ltd", a trial-balance import and a text document; `e2e-admin`, promoted by `scripts/admin-role.ts`; `e2e-plain`, no workspace) and saves their sessions in `e2e/.auth/` (gitignored). Four projects then run every spec: `mobile-light`, `mobile-dark` (375 px), `desktop-light` and `desktop-dark` (1440 px). `checkPage` fails a route that scrolls sideways, logs a console error or page error, or whose first Tab is not the skip link and second does not reach the content. Specs: `public.spec.ts` (18 routes and two cases), `workspace.spec.ts` (9 signed-in routes), `admin.spec.ts` (8 admin routes, a source and its published version, and a signed-in non-admin getting Page not found at `/admin` three times and at `/admin/facts`).

Last full run (2026-10-28, twice): `161 passed (5.0m)`, `161 passed (4.9m)` (1 setup + 80 public + 36 workspace + 44 admin). `calendar.spec.ts` (2 tests per project, a UK company made by API) was added after: `npm run test:e2e -- calendar` gave `9 passed (28.6s)`; the full suite has not been re-run since.
